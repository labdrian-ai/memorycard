# memorycard list — read-only listing by topic prefix
Objective: a read-only `memorycard list --topic-prefix` verb so labdrian's procedural-candidate scan reads memorycard through its public CLI instead of its private SQLite schema.

Source of truth: the labdrian-sdd-overlay feature document `odd/tasks/labdrian-orchestrator-opencode.md` (branch `feat/labdrian-orchestrator-opencode`), task T25a, design in its Log L37, owner decision in L35.

- S1. The owner chose option B for how labdrian reads memorycard, verbatim: "B" (overlay L35) — a new `memorycard list --topic-prefix --json` verb in this repository, not a read of the SQLite file.
- S2. Contract (overlay L37, extended here by `scope`, the order and the `--project` default; the overlay document records the extension for T25b): `memorycard list --topic-prefix P [--topic-prefix P2 ...] [--project NAME] [--json]`; literal prefix match, never `LIKE`; active memories only; writes nothing (no `use_count` or `last_used_at`); stored rows as they are, split parts included; JSON `{"project","memories":[{"id","topic_key","scope","title","body"}]}` with `memories` always an array (`scope` added in `30d4f03`, L3). Order: document key (a part `<key>/part-N` counts as `<key>`, its number read as an integer, so `part-02` is 2; a row that is not a part counts as number 0, so `<key>` comes before its parts), then part number, then id. `--project` defaults to the resolved project (the `list` handler takes `a.project()` as the flag default in `internal/cli/cli.go`; the chain is the usage text's `environment:` section: `MEMORYCARD_PROJECT`, a `.memorycard` file, the git remote name, the git root name, the directory name); every scope of that project is listed, so one topic key can come back once per scope, told apart by `scope`.
