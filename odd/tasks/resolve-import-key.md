# memorycard resolve — read-only lookup of import keys
Objective: a read-only `memorycard resolve --source S --key K` verb so labdrian counts one observation once when it is listed as `engram:<n>` and as `memorycard:<m>`, reading memorycard's `import_map` through its public CLI instead of its private SQLite schema.
Branch: feat/resolve-import-key (from main 0f273c8, which holds the `list` verb) | Delivery: one PR, owner's standing merge ok | Test runner: `go test ./...`

## Specs
Source of truth: the labdrian-sdd-overlay feature document `odd/tasks/labdrian-orchestrator-opencode.md` (branch `feat/labdrian-orchestrator-opencode`), task T25c, design in its Log L46; the verb's place in the engine (T25d) and the skill text (T23) are there too.

- S1. The owner chose to translate legacy ids, verbatim: "traducelos" (overlay L46, answer to "¿agregamos esa traducción para que no cuente doble, o aceptamos el doble conteo de las observaciones viejas?"). memorycard's own `import_map` is the only authority on which memory an Engram id became, so the engine asks memorycard through a new verb here, not through the SQLite file.
- S2. Contract (overlay L46): `memorycard resolve --source S --key K [--key K2 ...] [--json]`. `--source` is required and non-empty; at least one `--key`, each non-empty; no positional argument and no `--project` (`source_key` is the source's own id); otherwise exit 2 with `usage: memorycard resolve --source S --key K [--key K2 ...] [--json]` on stderr.
- S3. Per key, one select of the part-1 row of `import_map` (`select memory_id from import_map where source = ? and source_key = ? and part = 1`, the importer's own lookup at `internal/memory/import.go`). Read-only: no row of any table is written, no `use_count` or `last_used_at` touched. A key saved in parts resolves to its part-1 memory; two keys the import merged into one memory resolve to the same id; another source's key is never matched.
- S4. An unknown key (never imported, deleted in Engram before the import, redacted to nothing, not an Engram id) is reported, not an error, and the exit code is 0. `--json`: `{"source": "<S>", "ids": [{"key": "<K>", "memory_id": <n>|null}]}`, one entry per `--key` in the order given, duplicates echoed, `null` for unknown, exactly those keys. Text: one line per key, `<S>:<K> #<n>` or `<S>:<K> unknown`.
- S5. Docs: the usage text names `resolve`, and the README has a section under "What the commands return" and a pointer under "Importing existing memories".
